# RADAH MEMSHALAH Alignment — Revenue Engine

This is an implementation mapping, not a grant of authority and not a replacement for Dominion governance.

| Principle | Code control |
|---|---|
| Ordered authority | Default deny in `policy.py`; only explicit simulation actions are allowlisted. |
| Truth | `VERIFIED`, `INFERRED`, and `UNKNOWN` are first-class states. `VERIFIED` requires evidence references. |
| Stewardship | Opportunity scoring includes zero-capital fit; money uses `Decimal`; scaling follows observed funnel facts rather than promises. |
| Discipline | The learning loop proposes exactly one variable change per cycle. |
| Accountability | Every action request can produce a canonical SHA-256 decision receipt with reasons and evidence refs. |
| Restraint | Publishing, customer contact, spending/money movement, affiliate enrollment, pricing, revenue-wave activation, and deployment are blocked. |
| Reversibility | The package is pure/in-memory and side-effect-free; no network, process, browser, or external write capability is imported. |
| Purpose / revenue | It prioritizes buyer intent, demand, economics, evidence, zero-capital fit, and original value; it then measures clicks, conversions, commissions, and payouts. |

## Non-negotiable assertions

- AI output is not revenue evidence.
- An affiliate program is not usable merely because it exists; approval and terms evidence are required.
- A commission is not cash until payout evidence exists.
- No guaranteed-income/no-loss language is permitted.
- No fabricated first-hand testing or testimonial claim is permitted.
- Affiliate content must disclose the relationship and declare original value.
- The engine never promotes itself to production authority.
