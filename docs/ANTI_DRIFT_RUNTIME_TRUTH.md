# Anti-Drift Runtime Truth

A green repository check proves only the scope that check actually exercised. Dominion must not elevate a skipped external probe, a static configuration check, or a merged implementation to runtime truth.

For the current P0 revenue closure sprint:

1. Static/build proof validates implementation.
2. Deployment proof validates installation.
3. Runtime health proof validates reachability and loaded capability.
4. Transaction/attribution proof validates the revenue path.
5. Measurement and learning receipts validate adaptation.

Only the corresponding receipt can advance an item to DONE.
